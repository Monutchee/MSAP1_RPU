# AD7771 RPU interface

R5 core 0 owns the AD7771. The public C++ interface is
`common/include/ad7771.hpp`; applications do not access AXI registers or AD7771
register addresses directly.

## Default profile

- High-resolution mode
- Sinc5 filter
- 32 kSPS simultaneous sample rate
- 256 frames per DMA packet
- Eight signed, sign-extended 32-bit storage words per frame
- Runtime per-channel PGA factors of 1, 2, 4, or 8

The library also defines 1, 2, 4, 8, 16, 32, 64, and 128 kSPS profiles.
The sensor board supplies the AD7771 with a fixed 8.192 MHz MCLK, so this board
uses high-resolution mode; the AD7771 specifies a maximum 4.096 MHz MCLK in
low-power mode. The API still represents low-power mode for reuse with hardware
that provides a suitable clock, and rejects invalid clock/rate/decimation
combinations. The library keeps the four-lane data clock at MCLK and programs
the SRC decimation to select the sample rate.

The sensor-board schematic also labels the analog input low-pass sections at
approximately 12.5 kHz and identifies 32 kSPS as the board sample rate. Thus,
32 kSPS is a sensible first production profile (16 kHz Nyquist bandwidth).
Higher ODRs are supported for experiments and oversampling, but do not increase
the analog front-end bandwidth.

## Hardware contract

| Function | Address | Owner |
| --- | ---: | --- |
| AXI Quad SPI | `0xB0010000` | AD7771 register control |
| AD7771 capture registers | `0xB0020000` | PL receiver control/status |
| AXI DMA registers | `0xB0030000` | Linux meter DMA driver |
| ADC conversion registers | `0xB0040000` | R5c0 runtime configuration |
| Meter processing registers | `0xB0050000` | R5c0 runtime configuration |
| Raw ADC simulator registers | `0xB0080000` | R5c0 source/signal configuration |

The capture register at offset `0x2C` reports the external ADC DCLK frequency,
and offset `0x30` reports the `ADC_DRDY_N` high-to-low frame-indication rate.
PL measures both against `pl_clk0` over a one-second window. R5c0 includes
these values in ADC health responses so Linux can distinguish an ADC output
data-rate problem from receiver, DMA, or downstream metering behavior. The
same response contains the active channel configuration, general
configuration, DOUT/SRC configuration, per-channel offset/gain calibration,
channel errors, saturation errors, general errors, enables, and status
registers needed to diagnose a persistent AD7771 alert without direct Linux
SPI access.

Vivado's implemented address map and exported XSA both place AXI Quad SPI at
`0xB0010000`. Vitis 2025.2 may flatten that IP inside the block-design
container as `0xA0000000` in its generated SDT. The library uses the generated
entry to obtain the `XSpi` capabilities, then passes `0xB0010000` as the
effective hardware address to `XSpi_CfgInitialize()`.

The PL emits one AXI4-Stream beat per channel in channel order 0 through 7.
Each beat is a sign-extended 24-bit sample in a 32-bit word. `TLAST` is asserted
after `frames_per_packet * 8` beats, so a 256-frame packet occupies 8192 bytes.

Linux owns the scatter-gather AXI DMA channel, its descriptors, interrupts, and
CMA-backed buffers. R5c0 neither includes the AXI DMA driver nor maps meter
record DDR. Raw frames remain inside PL after capture: `AdcConversion` applies
runtime Q16.16 coefficients, `MeterProcessing` calculates mean-corrected RMS,
and the Meter Result Hub emits one 256-byte periodic result record to DMA.

## Startup sequence

`Ad7771::initialize()` performs device configuration only:

1. Initialize AXI Quad SPI in mode 0.
2. Pulse the active-low AD7771 RESET input and wait for `INIT_COMPLETE`.
3. Enable the internal 2.5 V `REF_OUT` buffer which feeds the sensor board's
   external reference-divider/buffer circuit, wait for it to settle, and
   configure power mode, sinc filter, four DOUT lanes, status headers,
   per-channel PGA, and the requested SRC decimation.
4. Pulse the AD7771 `START` pin high for 10 µs. The ADC synchronizes that pulse
   to MCLK and emits it on `SYNC_OUT`; the sensor board loops `SYNC_OUT` to
   `SYNC_IN`, resetting the digital filters without changing registers. This
   hardware path avoids the ambiguous `START` gating of the SPI_SYNC bit.
5. Program the PL packet length and leave capture disabled with its FIFO reset.
6. Return `START` low. AD7771 START is a positive synchronization pulse, not an
   active-low conversion enable; the legacy `_N` PL signal name follows the
   board net name and does not describe its logical polarity.

Linux first opens `/dev/msap1-meter`, which arms AXI DMA, stops capture, then
sends `METER_CONFIG_SET`. R5c0 validates the requested sample rate, window,
channel mask, per-channel PGA factors, and unsigned Q16.16
micro-unit/count coefficients. The same version-2 request carries the fixed
CH6/VLA frequency mode, rolling window, 10–200 Hz limits, hysteresis, and the
declared nominal grid frequency (50 or 60 Hz only). R5c0 derives the IEC
61000-4-30 basic-block cycle count from the nominal frequency (50 Hz -> 10
cycles, 60 Hz -> 12 cycles; the count is never on the wire) and packs it with
the nominal frequency and cycle-timing enable into the processing block's
`GRID_SHADOW_CONFIG` register at offset `0x6C`; `GRID_ACTIVE_CONFIG` at `0x70`
reads back the applied value and read-only `GRID_STATUS` at `0x74` reports
reference lock and cycles elapsed in the current block. Cycle timing is
always enabled; the PL falls back on its own to the sample-count RMS window
(offset `0x18`, still derived by Linux and passed through unchanged) when the
voltage reference is lost. While capture is stopped R5c0 programs and reads
back all eight AD7771 channel gains, synchronizes the digital filters, writes
the conversion and processing shadow registers, applies RMS, frequency, and
grid-timing configuration atomically with the same control toggle, and
acknowledges only after active-generation, frequency-register, and
`GRID_ACTIVE_CONFIG` readback. Frequency results remain in MTR1 DMA records and
never travel over RPMsg. Linux then sends the payloadless
`ADC_CAPTURE_START` command. For shutdown Linux sends `ADC_CAPTURE_STOP` before
closing the meter device. Samples and meter records are never sent over RPMsg.

ADC health compares the one-second PL DRDY measurement against the requested
sample rate with a 1% tolerance. A missing or mismatched measurement clears the
rate-match flag even when SPI register readback is otherwise correct.
Register-health reads retry a malformed SPI response up to two times before
reporting the audit as failed. The health payload includes cumulative malformed
header and retry-recovery counters plus the last affected register/header so
Linux can distinguish a recovered transient from a persistent SPI fault.

## ADC source abstraction

R5c0 exposes ADC lifecycle through `AdcDevice`. `Ad7771` implements physical
SPI, reset, synchronization, and capture control; `AdcSimulator` implements
the PL generator's shadow/apply/readback register contract. `AdcController`
owns both statically allocated devices and performs source changes as a single
transaction: stop, configure the target, apply/read back the source mux,
commit the generation, and restart if capture was previously active. Any
failure restores the previous source and configuration.

The simulator emits signed 24-bit-compatible raw samples before conversion,
so conversion, RMS, frequency, meter DMA, and waveform capture exercise the
same downstream chain as physical input. While simulation is selected, R5c0
does not touch AXI Quad SPI; physical register diagnostics are reported as not
applicable and simulator generation/counters determine source health.

## Changing the rate

The default boot configuration remains 32 kSPS. Linux can temporarily select
any declared discrete rate through the acquisition daemon:

```sh
mnc adc rate --sps 16000
mnc adc rate --sps 32000
mnc adc rate --sps 64000
```

`METER_CONFIG_SET` carries the selected rate together with the recalculated RMS
and frequency windows. R5c0 accepts the change only while capture is stopped,
programs all channel PGA values, explicitly reloads the SRC with a
`0 -> 1 -> 0` software-update sequence, waits for the new ODR and sinc filter
to settle, and then commits the PL configuration. Linux owns the coordinated
stop/restart and rollback sequence.

The selection is diagnostic and is not persisted. Restarting
`msap1-fpga-acquisition` restores 32 kSPS.

## Flow-1 reset/SRC diagnostic

`mnc adc testflw --flow 1` runs a coordinated destructive diagnostic while
Linux DMA and PL capture are stopped. R5c0:

1. Captures active SPI, DCLK, and DRDY state.
2. Drives the existing PL `ADC_RESET_N` output low for 2.2 seconds so the PL
   frequency meters contain a complete reset interval.
3. Releases reset, waits for `INIT_COMPLETE`, and captures reset-default
   register state before any configuration writes.
4. Restores the current power/filter/DOUT/PGA configuration.
5. Loads SRC with a deliberately observable `0 -> 1 ms high -> 0` sequence,
   reading `SRC_UPDATE` at both levels.
6. Synchronizes the filters, waits for fresh one-second DCLK/DRDY windows, and
   captures the final active state.

The long waits use `vTaskDelay`, so the lower-priority RPU heartbeat task
continues to run. This is a warm AD7771 hardware-pin reset, not an ADC power
cycle and not an FPGA/Linux reset. The acquisition daemon restores its prior
running state without issuing another SRC load after a successful flow.
